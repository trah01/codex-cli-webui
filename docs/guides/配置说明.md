# 配置说明

[文档目录](../README.md) · [项目首页](../../README.md)

## 设置

在侧边栏打开设置，可修改外观、语言、模型、推理强度、权限、全局指令等。开关和下拉选项修改后立即应用；文本编辑完成后自动保存。部分 Codex 配置仅对新会话生效，以页面反馈为准。

安全设置提供账号密码、通行密钥、访问域名、二次验证和统一身份登录：

- **账号密码**：密码长度为 12–256 个字符；修改凭据会使已有登录会话失效。本机登录默认开启。
- **访问域名**：用于受控入口下的域名校验，不会创建 DNS、配置证书或限制网络端口。绑定域名不代表可以公网开放。
- **二次验证**：密码登录可使用验证器动态验证码，启用前需完成密钥登记和当前验证码校验。
- **统一身份登录**：先绑定受控入口域名，将页面提供的回调地址配置到身份提供方，再填写客户端信息。身份提供方的登录权限必须限制在可信人员范围内；本项目没有独立的用户允许名单。OIDC 的二次验证应在身份提供方配置。

所有获准访问的用户操作的是同一个 Codex 实例和服务器工作环境。**本项目不提供多租户隔离，也不适合向不可信用户共享。**

## 通行密钥（Passkey）

先通过已有登录方式进入应用，再打开“设置 → 安全 → 通行密钥”，填写可选的设备名称并添加。按系统提示使用指纹、面容、设备 PIN 或安全密钥完成验证。添加和移除需要最近 5 分钟内验证过身份，超时后页面会要求重新验证；支持查看和移除已添加的密钥。

- **本机**：使用 `http://localhost:8899`。从 `127.0.0.1` 打开设置时，页面会提供切换入口。
- **远程**：使用通过堡垒机安全网关访问的 HTTPS 域名；普通 HTTP 域名无法使用 Passkey。
- **地址绑定**：本机与远程域名需要分别添加密钥，更换域名后也需要重新添加。
- **验证方式**：Passkey 登录要求设备验证身份，可独立完成登录，无需再填写密码或密码登录所用的 OTP。已配置的密码和 OIDC 登录方式继续可用。
- **数据**：服务端仅保存公钥和密钥元数据，存储文件为认证文件旁的 `.passkeys.json`，私钥由设备或密码管理器保管。备份认证数据时应包含此文件。
- **移除与恢复**：移除密钥会退出其他登录会话。设备丢失时，可使用其他已配置的登录方式进入设置并移除对应密钥。

这些密钥均可登录同一个共享实例，请只为可信人员和设备添加。

## 环境变量

通常使用默认配置即可。完整示例见 [.env.example](../../.env.example)。

| 环境变量 | 默认值 | 用途 |
| --- | --- | --- |
| `HOST` | `127.0.0.1` | 服务监听地址，建议保持默认 |
| `PORT` | `8899` | 服务端口 |
| `CODEX_WEBUI_CWD` | 项目自身目录 | 默认工作目录 |
| `CODEX_WEBUI_REVIEW_ROOT` | 默认工作目录 | 允许撤销和重新应用的 Git 仓库根目录 |
| `CODEX_HOME` | `~/.codex` | Codex 配置和状态目录 |
| `CODEX_WEBUI_APP_SERVER_MODE` | `auto` | `auto` 优先共享后台；`shared` 只使用共享后台；`standalone` 使用独立后台 |
| `CODEX_WEBUI_APP_SERVER_SOCKET` | Codex 状态目录下的默认套接字 | 指定共享后台连接位置 |
| `CODEX_AUTH_PATH` | `$CODEX_HOME/auth.json` | 指定 Codex 认证文件 |
| `CODEX_WEBUI_AUTH_STORE` | `$CODEX_HOME/codex-webui-auth.json` | WebUI 账号凭据与相关存储的基础路径 |
| `CODEX_WEBUI_PASSWORD` | 未设置 | 通过启动环境指定登录密码；优先于网页管理的密码 |
| `CODEX_WEBUI_ACCESS_TOKEN` | 未设置 | 密码模式下供程序使用的独立 Bearer 令牌；启用 OTP 或 OIDC 后停用 |
| `CODEX_WEBUI_NTFY_TOPIC` | 未设置 | 可选的任务完成通知主题 |
| `CODEX_WEBUI_NTFY_URL` | `https://ntfy.sh` | 可选的通知服务地址 |

`.env.example` 不会自动加载。需要使用配置文件时，将其复制为 `.env`，按实际情况填写，并显式加载：

```bash
cp .env.example .env
node --env-file=.env --import tsx server/index.ts
```

也可以通过服务管理器注入环境变量。不要提交包含密码、令牌或客户端密钥的 `.env` 文件。

## 数据与权限

Codex 登录信息和状态默认位于 `~/.codex`。WebUI 的密码校验信息、域名和认证配置，以及消息队列、会话记录和草稿等数据保存在认证存储文件附近。调整 `CODEX_WEBUI_AUTH_STORE` 时，应一并考虑这些数据的迁移与备份。

会话和附件可能包含源码、命令、文件路径及业务信息，应与服务器上的其他敏感数据一起保护。启用任务通知前，确认通知主题和通知服务的可见范围。

终端和 Codex 使用服务进程所属用户的权限。建议使用专用的普通用户运行，只授予所需项目目录的访问权限。审批前应阅读具体命令和文件变更，谨慎启用不受限制的访问模式。
