# 部署与访问

[文档目录](../README.md) · [项目首页](../../README.md)

> [!CAUTION]
> **禁止将 WebUI 直接对公网开放，即使已配置鉴权和 HTTPS。** 本项目具备命令执行和文件读写能力，后端必须保持网络隔离。

## 推荐访问方式

本机使用时，直接访问 `http://127.0.0.1:8899`。远程使用时，通过堡垒机的安全网关反向代理访问，由网关负责访问认证与授权，WebUI 后端仅允许安全网关连接。

网关与 WebUI 在同一台服务器时，保持监听 `127.0.0.1`；分开部署时，使用隔离的内部网络，并通过防火墙限制来源。反向代理应支持 WebSocket 和流式响应，域名校验与认证配置见 [配置说明](./配置说明.md)。

## Docker

仓库提供 [Dockerfile](../../Dockerfile) 和 [docker-compose.yml](../../docker-compose.yml)。现有 Compose 配置默认仅将服务发布到宿主机的 `127.0.0.1:8899`，应保持这一访问边界。

使用前需要准备与 Linux 容器架构匹配的 Codex 可执行文件，配置 `CODEX_BIN`、允许审查的仓库路径和 Codex 状态目录，并确认挂载目录的权限。容器只能访问实际挂载到其中的项目；容器内的路径与宿主机路径需要分别核对。不要直接将 macOS 的 Codex 可执行文件挂入 Linux 容器。

容器内监听 `0.0.0.0` 是为了接收容器网络连接，不代表应将宿主机端口对公网发布。不要将 `WEBUI_BIND_IP` 改为公网监听地址，也不要额外挂载宿主机 Docker Socket。
