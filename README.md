# codex-cli-webui

通过浏览器使用 Codex 的个人开发工作台，集中处理项目会话、代码修改、执行审批和终端操作，支持桌面与移动端。

[English](./docs/en/README.md)

灵感来源于 [lezi-fun/codex-webui](https://github.com/lezi-fun/codex-webui)，并在此基础上进行了大量优化。

> [!CAUTION]
> **禁止将本项目直接对公网开放。即使已启用密码、动态验证码或统一身份登录，直接开放到公网仍然非常危险。**
>
> 本项目能够调用终端、执行命令、读取和修改文件，并使用运行环境中的 Codex 权限与凭据。登录保护不能替代网络隔离，也不能把它变成适合公网使用的服务。不要将服务端口、普通反向代理或内网穿透入口直接对公网开放；启用 HTTPS 同样不能替代访问控制与网络隔离。
>
> 远程使用时，通过堡垒机的安全网关反向代理访问，WebUI 后端仅允许安全网关连接。


## 功能

- **会话与项目**：切换项目目录、管理历史会话、接收流式回答，查看模型、推理强度与上下文用量。
- **持续执行**：展示工具调用和任务状态；会话被其他 Codex 客户端占用时，消息进入队列，支持取消和重试。
- **审批与问答**：处理命令执行、文件修改和权限请求，显示请求的提交与处理状态。
- **代码审查**：查看统一或左右对照的代码差异，支持换行、展开，以及指定仓库范围内的撤销和重新应用。
- **工作面板**：集成交互式终端、文件浏览与预览、文件位置跳转、网页入口和子代理会话管理。
- **消息与草稿**：支持 Markdown、表格、代码块、公式和图片附件，保存输入草稿与会话记录。
- **设置与界面**：提供中文和英文、浅色和深色主题、界面缩放、分组设置及自动保存，适配桌面与移动端。
- **访问控制**：支持账号密码、通行密钥（Passkey）、动态验证码（OTP）和统一身份登录（OIDC）。这些功能用于受控环境内的访问保护，不代表允许公网开放。

本项目连接真实的 `codex app-server`。默认优先连接本机已有的共享后台；无法使用时启动独立后台。部分能力取决于本机 Codex 版本、账号和运行环境。

## 环境要求

- Node.js **24.22.1 及以上的 24.x**，或 **26.12.1 及以上的 26.x**，以及 npm。
- 已安装并完成登录的 [Codex CLI](https://www.npmjs.com/package/@openai/codex)。
- Git；代码审查中的撤销和重新应用需要使用 Git。
- 推荐 macOS 或 Linux，Windows 尚未完整验证。

尚未安装 Codex CLI 时，先执行：

```bash
npm install -g @openai/codex
codex
```

按提示完成登录，再启动 WebUI。

## 本机启动

在项目目录中执行：

```bash
npm ci
npm start
```

打开 **http://localhost:8899**。默认只监听 `127.0.0.1`，端口为 `8899`。

首次使用时，在服务器本机页面完成账号密码设置，再选择项目目录开始会话。认证配置入口仅接受直接通过 `127.0.0.1` 或 `localhost` 访问；IPv6 回环地址形式、其他 IP、域名和代理转发请求不能用于管理本机配置。

通行密钥只能通过服务器本机的 **http://localhost:8899** 管理，入口为“设置 → 安全 → 通行密钥”。远程访问仅支持使用当前域名已有的通行密钥登录，不显示管理入口；本机密钥不能用于远程域名。密码仍可作为备用登录方式。

## 安装成应用

使用 Chrome 通过 `http://localhost:8899` 或受控 HTTPS 域名打开页面，浏览器识别后可通过地址栏安装图标或浏览器菜单安装成应用。安装后以独立窗口打开，仍需连接运行中的 WebUI 服务。

## 云服务器配置

可以使用端口转发进入本机设置页，也可以使用环境变量完成账号、域名、动态验证码和统一身份登录配置。

**端口转发**：在自己的电脑上执行，将示例用户名和服务器地址替换为实际值：

```bash
ssh -N -L 8899:127.0.0.1:8899 用户名@服务器地址
```

保持连接，在自己电脑的浏览器打开 `http://localhost:8899`。转发后的连接按服务器本机访问处理，可在“设置 → 安全”管理账号、访问域名等配置。若本地 8899 端口已占用，将命令中第一个 `8899` 改为其他空闲端口，并使用对应端口访问。

**环境变量**：将 [.env.example](./.env.example) 复制为 `.env`，至少填写登录密码；需要远程域名访问时，同时填写域名及 HTTPS 来源地址：

```dotenv
CODEX_WEBUI_USERNAME=your-user-name
CODEX_WEBUI_PASSWORD=REPLACE_WITH_A_LONG_RANDOM_PASSWORD
CODEX_WEBUI_DOMAIN=codex.example.com
CODEX_WEBUI_PUBLIC_ORIGIN=https://codex.example.com
```

用户名可选。修改配置后，通过以下命令加载 `.env` 并启动服务：

```bash
node --env-file=.env --import tsx server/index.ts
```

也可以由服务管理器或容器注入相同环境变量后执行 `npm start`；`npm start` 不会自动读取 `.env`。网页已保存的域名与认证选项优先于对应环境变量，账号密码环境变量则优先于网页凭据。其他选项见 [配置说明](./docs/guides/配置说明.md)。
